# PP-OCRv5 recognition models

`PlateRecognitionOCRV5` deploys two recognition specifications. Both models use
TensorRT 8.2.5.1-compatible ONNX IR 6/opset 11 graphs, accept FP32
`x [N,3,48,W]`, and produce FP32 `fetch_name_0 [N,T,18385]`.

The Mobile deployment graph is reproducibly converted to opset 11 and assigned
IR version 6. The Server deployment graph is an exact byte-for-byte copy of its
already compatible source. The preparation script verifies the source and
deployment hashes, runs the full ONNX checker, and validates the IR/opset and
I/O contract before atomically installing either file.

No deployment dictionary is required or copied. Mobile and Server each have an
explicit sparse mapping from their native 18,385 classes to the 77 characters
supported by `PlateRecognition`; both mappings are embedded in the C++ source.
Unmapped native classes are omitted from final text while still participating
in CTC repeat/blank processing.

Prepare or validate both models with the project's existing Python environment:

```powershell
& 'P:\Algorithm\Plate\PlateRecognition_Android\.tools\python311\python.exe' `
  PlateRecognitionOCRV5\tools\prepare_models.py
```

By default an existing valid target is only revalidated. Use `--force` to
regenerate it with a temporary file followed by an atomic replacement. Use
`--variant mobile` or `--variant server` to prepare only one specification.

TensorRT engine caches must be generated by TensorRT 8.2.5.1 on the deployment
GPU. Do not reuse engines built by another TensorRT release or GPU architecture.
